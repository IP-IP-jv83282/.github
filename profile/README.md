<h2>先认清自己买的是哪一种计价模型</h2>
<p>海外住宅 IP 的报价看起来五花八门，本质上只有三种模型：按 IP 条数包月、按流量计费、底价加超额的混合制。同一个供应商对同一批资源，用三种模型算出来的价格可能差两三倍，所以第一步不是比价，而是先确认对方报的是哪一种。</p>
<p>搞错模型的后果很直接：拿按流量报价的低价去对比包月价，以为捡了便宜，实际跑一个月批量任务，流量费能翻五倍。下面把三种模型拆开讲，再谈 IP 数量该怎么定。</p>

<h2>按条数包月：最常见也最好算</h2>
<p>这种模式下，一条独享静态住宅 IP 一个月的价格是固定的，用多少流量都不额外收费。优点是预算可控，缺点是买多了浪费。绝大多数做店铺运营的团队用的是这种，因为每天操作量比较稳定，流量不会大起大落。</p>
<p>价格通常按采购量分阶梯，买得越多单价越低。真实阶梯一般长这样：1 到 5 条一个价，6 到 20 条降一档，21 到 50 条再降一档，50 条以上进入议价区间。拐点各家不同，但规律一致，量越大单价越低，降幅在靠近拐点时最明显。</p>

<h2>按流量计费：单价看着低，风险在尾部</h2>
<p>按流量计费通常以 GB 为单位，常见于动态住宅代理池。好处是入门门槛低，用一点付一点；坏处是流量消耗完全不受你控制。一次后台页面加载可能几十个请求，一个商品批量上传带十几张高清图，几百 MB 就没了。</p>
<p>这种模式适合两类人：一是用量很小、只做偶尔查询的；二是用量极大、有能力自己做请求优化的。处在中间的大多数团队用按流量计费，十有八九会超预算，因为你无法预测这个月平台会改什么版、图片会不会变大。</p>

<h2>混合制：底价保底，超出部分另算</h2>
<p>混合制是固定条数包月加超出流量按 GB 计。它把前两种的优点拼在一起：基础额度内价格可预期，突发流量也不会直接断线。缺点是合同条款更复杂，一定要看清超额单价和是否自动续费超额包，有的供应商超额单价是正常价的数倍，一旦触发就很贵。</p>

<h2>IP 数量按什么定，别凭感觉</h2>
<p>实用的算法是账号数乘以 1.2 到 1.5，再向上取整。多出来的部分是备用和轮换用的，某个 IP 状态不好时能立刻替换，不至于让账号停摆。如果账号分散在不同平台、不同站点，还要按一个站点一组 IP 再分一次，避免同一 IP 跨平台使用形成关联。</p>
<p>另一个维度是并发。一个 IP 上同时在线几个账号，比一个 IP 一共服务过几个账号更危险。稳妥的做法是一个 IP 对应一个主力账号，短期临时登录用备用 IP，用完即退。</p>

<h2>为什么第 11 条比第 10 条便宜，第 51 条又变贵</h2>
<p>阶梯价在拐点处会有一次明显下跳，因为供应商的采购成本也是按整段资源谈的，跨过某个数量他就拿到了更低的批发价。而在更高区间出现价格反弹，通常不是涨价，而是你要的东西变特殊了，比如要求同一州、同一城市甚至同一运营商，资源稀缺，价格自然上去。</p>
<p>所以询价时把地区精度和运营商要求一起报出去，别等谈好价格再补充，否则对方会以定制资源为由加价。</p>

<h2>询价单上必须写清的四个数字</h2>
<p>一是 IP 条数和地区精度，国家级、州级、城市级价格完全不同；二是独享还是共享，共享的还要问同时在线人数上限；三是计费周期和是否支持按月退订；四是 IP 更换频率和更换是否收费。这四项不写清，后面每一个都可能变成额外账单。</p>

<h2>砍价的三个真实抓手</h2>
<p>第一是预付周期，季付、年付通常能拿到折扣，但要先确认退款条款；第二是凑单，差几条就到下一档时补齐比原价更省；第三是打包，把不同地区的需求合到一个订单里，总量上去单价就下来。</p>
<p>不建议一上来就压价到成本线以下，供应商会用质量更差的资源补回来，最后吃亏的是你。合理的做法是压价的同时把服务指标写进合同，价格和服务一起谈。</p>

<h2>常见问题</h2>
<h3>50 条 IP 大概什么价位</h3>
<p>没有统一答案，取决于地区精度、独享与否、是否同运营商。询价时把这三项讲清楚，拿到三个供应商的报价对比，比问大概多少钱有用得多。</p>
<h3>能不能先买一条试用</h3>
<p>多数供应商支持，但试用 IP 通常不是正式资源，测出来的质量会偏好。更有意义的是买 3 条正式 IP 跑一周，专门看晚高峰表现。</p>
<h3>按流量买怎么控制不超支</h3>
<p>关掉图片自动加载、把批量任务拆到不同时段、用脚本做请求去重，这三件事能砍掉大半流量。做不到的话，还是回到包月更稳。</p>
<h3>年付折扣大，值得吗</h3>
<p>值得的前提是供应商稳定，且合同里有 IP 更换和无理由退款条款。年付锁死价格的同时也锁死了选择权，第一次合作建议先季付观察。</p>
